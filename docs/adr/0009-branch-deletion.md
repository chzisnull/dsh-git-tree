# 本地强制删除与远程分支删除

2026-11-04。发布前用户追加删除能力，并明确确认：远程删除实际删除服务器分支；强制删除针对未合并的本地分支。此决定扩展 ADR 0008 中远程行只读的边界。

## 交互

- 本地分支提供普通删除（默认 `git branch -d`）和独立的“强制删除分支…”（`git branch -D`）。两项均禁止删除当前分支；其他 worktree 占用的分支由 Git 拒绝。
- 远程跟踪分支菜单增加“删除远程分支…”，保留浏览、复制功能，不增加检出、重命名或合并入口。
- 2026-11-04 后续调整：用户要求简化操作。远程删除、本地强制删除和普通本地删除统一使用弹窗二次确认，不再要求输入分支名称；确认框显示删除对象和影响，用户点击删除后执行。
- 开启或取消确认框不发送删除请求。请求进行中禁止重复提交；切换仓库后旧确认失效。失败保留对话框并显示原因。
- 成功刷新状态、引用树及当前历史。仅在当前筛选精确指向已删除的相同种类引用时清除筛选，不混淆同名本地与远程分支。

## 宿主契约

- `POST /api/git-tree/branch/delete` 接受 `{ name, force?: boolean }`。只有显式 `force: true` 才使用 `-D`；错误类型拒绝，绝不在普通删除失败后自动改为强制。
- `POST /api/git-tree/branch/delete-remote` 接受 `{ name, expectedOid }`。`name` 是完整跟踪名称（如 `origin/feature/a`），`expectedOid` 绑定用户确认时的快照。
- 从已配置远端与 fetch refspec 解析唯一的服务器 `refs/heads/<branch>`。无法唯一映射、负 refspec 排除、映射到标签或多 push URL 时拒绝，避免扩大删除对象。
- 使用单一明确 push 目标与精确删除 refspec；删除绑定完整提交 OID 的 lease。推送前快照或远端已更新则拒绝，服务器权限和保护规则仍生效。不会无条件 force，也不会删除本地同名分支。
- 服务器删除成功后以原 OID 为条件清除本地跟踪引用。若同时发生 fetch 导致清理失败，仍返回服务器删除成功并携带警告，保留新的本地引用，避免将部分清理失败伪报为删除失败。

## 验证

使用隔离本地 bare remote 断言服务器引用实际消失、本地分支保留、未合并普通删除拒绝而强制删除成功、当前或其他 worktree 分支拒绝、服务器更新竞态、保护 hook 拒绝、复杂 fetch 映射与多 URL 拒绝，以及删除成功但本地清理竞争的部分成功结果。客户端行为测试覆盖危险菜单、无需输入的二次确认、重复提交阻止、取消、错误保留、仓库切换和同名引用筛选刷新。
