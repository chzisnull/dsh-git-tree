# 提交信息交给 DSH 的模型来写

用户在提交卡片上要一个「按选中的文件生成提交信息」的按钮，并且要能从 DSH 的模型列表里配置默认用哪个模型。这条能力不是 Git 写操作，但它要发数据出去，所以单独记一条决定。

## 决定

- **模型来源只用 `ctx.llm`**：模型列表来自宿主 LLM 服务的 `listProviders()` + `listModels()`，就是 DSH 模型选择器展示的同一份实时目录；插件不读配置文件、不自己维护 provider 表。每个提供方的目录失败单独汇报，不拖垮整个列表。
- **选择存自己的文件**：`$DSH_HOME/git-tree/ai-settings.json`。不写 DSH 的 `agent-default-model` 设置——那是用户给 Agent 的默认模型，不该被面板改动。
- **没有保存过就用 DSH 默认 Agent 模型**；但只有该路由仍在目录里时才用。默认模型的路由漂移（配置改了、模型下线）时显示「选择模型」，不去调用一条必然失败的路由。
- **发什么由提交决定**：有暂存就发暂存文件的 diff，没有就发工作区文件的 diff；未跟踪文件只给路径。diff 上限 24 KB 并标注截断，文件数上限 60，输出上限 4000 字符。
- **只填输入框**：生成结果写进提交信息输入框，永不自动提交、不自动暂存、不改文件。用户可以改、可以清空。
- **失败分型**：缺凭据、限流、模型不可用、模型想调用工具、空回复、超时，各自映射到自己的错误码和中文提示，而不是一句「生成失败」。

## 结果

- 面板多出两个请求：`GET /api/git-tree/ai/models`、`POST /api/git-tree/ai/model`，以及一个生成请求 `POST /api/git-tree/commit-message`。
- 生成的调用是一次性的文本请求：不带工具、不带会话历史、`purpose` 留空，只带 system 提示与「文件列表 + diff」一条 user 消息。模型若坚持要调工具，按失败处理并提示换模型。
- 数据边界写进 README：所选文件的 diff 会发给你选中的模型；插件不发送历史、凭据或会话内容。
