# 冲突文件给 AI 解决，先预览再落盘

早先 ADR 0001 与 spec 0002 都把「冲突解决 UI」划在范围外，理由是冲突解决容易做半套、把用户的工作区改坏。用户后来明确要求两件事：**遇到冲突时右侧要能看到冲突内容**（当时面板对冲突文件显示「该文件没有差异」），以及**可以把冲突交给 AI 解决**。这条边界由此反转，记录决定与护栏。

## 决定

- **冲突文件按工作区文件展示，不解析 combined diff**。未合并路径的 `git diff` 输出是 `diff --cc` + `@@@` 双列前缀，语义晦涩；面板展示的应是「现在磁盘上这份带 `<<<<<<<` 的文件」——它同时也是 AI 要改、要写回的那份。解析在宿主做（`parseConflictText`），浏览器只渲染 `ours / theirs / base / marker-* / context` 五种行。
- **AI 只改工作区文件**：resolve 路由读冲突文件、调 DSH 的模型、校验输出（无冲突标记、非空、≤512KB），**不写盘**；写盘是单独的 apply 路由，前端必须先看预览（完整结果 + 与当前冲突文件的统一 diff）再点「应用」。
- **可撤销**：写盘后仍可用 `git checkout --merge -- <path>` 还原冲突标记，面板提供「还原冲突」按钮并二次确认；不引入插件自建的备份目录。
- **不自动 stage**：「应用」只写文件；「标记为已解决」是独立动作（`git add`），且文件里还有标记时直接拒绝。提交阻断保持现状——有冲突不能提交。
- **模型复用**:冲突解决与提交信息共用同一份「提交信息模型」设置与 `ctx.llm` 调用路径，不新增第二套模型配置。
- **只覆盖 merge/checkout 产生的本地冲突**：不改 rebase、stash、冲突编辑器（手工三栏合并）这些仍不做的能力。

## 结果

- 宿主新增 4 条路由：`conflict/resolve`、`conflict/apply`、`conflict/revert`、`conflict/mark-resolved`；`diff` 路由遇到未合并路径时返回冲突负载而不是空 diff。
- 面板右侧的多余空态「该文件没有差异」在冲突文件上不再出现；取而代之是冲突块高亮与三个动作。
- README 的状态表与能力清单同步；ADR 0001 里「冲突解决 UI 不做」的条款由本 ADR 取代。

## 后续（0.12.0）

冲突文件的头部主动作在 ADR 0006 里改成了「交给 AI 助手」：把上下文交给该仓库的 DSH 会话，由能读文件、能跑命令的 Agent 处理。本 ADR 的「模型合并 → 预览 → 应用」仍然存在、仍然按这里写的护栏执行，入口移到了冲突文件行的右键菜单（「用模型合并（预览）」）；「标记为已解决」「还原冲突」不变。
