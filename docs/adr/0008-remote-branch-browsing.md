# 远程分支浏览与审查修复

2026-11-04。用户确认：补齐远程分支只读浏览，同时修复本轮 review 确认的 11 项问题。后续功能单独排序，不纳入本次实现。

## 决定

本决定覆盖 spec 0002、ADR 0001 与 ADR 0004 中“远程分支展示不做”的条款，其余远端写操作边界保持原有语义。

- 左栏增加远程分组，按已配置远端名的最长前缀归组；保留 `feature/a/b` 完整分支名。无法对应配置的跟踪命名空间仍可浏览。
- 分组可展开收起；显示本地已经获取的远程跟踪引用，不将其描述为服务器即时清单。
- `for-each-ref` 读取 `%(symref)`，过滤 `origin/HEAD` 等符号别名，计数只包含实际引用。
- 远程行单击、Enter/空格与菜单“历史”使用 `remote:<完整跟踪名>` 浏览历史。复制保留 `origin/feature/a` 等完整名称。双击不检出，菜单只提供历史与复制。
- 历史查询使用完整 `refs/remotes/<name>`；“所有分支”包含远程独有提交，提交标记区分本地、标签和远程引用。未知 scope 拒绝，避免误回落到其他历史。
- 明确区分加载、读取失败、未配置远端和远端尚无已获取分支。选中远程引用消失时提示清除筛选或重新获取。
- 继续复用焦点感知轮询与引用树的 10 秒节拍。手动获取后刷新当前历史；不新增定时联网、获取全部远端或远端写接口。现有获取仍选择当前上游远端，回退 origin 或首个远端。

## 修复约束

1. 放弃更改和删除被跟踪文件必须使用字面文件路径与文件级校验，避免 `*`、`[]` 或 Git pathspec 魔法扩大范围。
2. 状态提供的路径以仓库根为基准；diff、AI diff、冲突、放弃、删除、暂存等文件操作统一基准，并检查仓库根仍在允许范围。
3. Git 执行器建立实际运行期限；终止宽限时间与运行期限是两个参数。取消与超时需要终止子进程。
4. 引用树、diff、历史、提交详情及提交文件 diff 只接受当前仓库与当前请求的结果；旧响应不得改写 loading/error。
5. 前台轮询与手动刷新重新读取当前 diff，涵盖同一文件持续为 M 但内容改变的情况。
6. 状态签名覆盖远端列表、作者信息等实际展示字段。
7. 标签右键完整传递回调。
8. 冲突预览返回绑定仓库、路径、源文件字节的 `sourceHash`；应用必须提交此摘要，来源变化返回冲突错误。切换仓库清除预览。
9. 冲突解析和解决前校验共同支持 Git 可变长度冲突标记。
10. 提交文件列表采用 `--name-status -z`，保留中文、空格、换行、制表符及重命名路径。
11. Git 失败保留标准输出中的诊断，真实合并冲突能够映射到可读的冲突状态。

验证使用已有 Node 路由测试、隔离真实 Git 仓库与可控制响应顺序的客户端行为回归，不增加测试框架或运行依赖。

## 后续优先级

用户选择优先改善“检查并提交自己或 Agent 的改动”：

1. 未跟踪文件内容预览：提交前可以检查新文件。
2. 按区块暂存与取消暂存：将同一文件中的不同目的拆成独立提交。
3. 分支比较：展示双方独有提交、变更文件与 diff。

随后再评估创建并检出远程跟踪分支、按远端获取和最近获取结果、分支搜索/收藏、合并继续/中止、将指定文件或提交交给 Agent review。跟踪检出需要明确本地同名冲突与创建成功但切换失败的行为；本次不提前加入这些写操作。
