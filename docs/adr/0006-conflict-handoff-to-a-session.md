# 冲突交给会话，而不是在面板里补全

0.8.0 的做法是「AI 解决」：把冲突文件整份发给一个模型，拿回完整文件，预览 diff，点应用才写盘。实际用起来的问题不在写盘那一步，而在它只能做「一次性补全」——模型看不见项目其余部分，不能跑测试，也不能追问；用户用真实冲突试过之后明确要求：点「AI 解决」应该在 DSH 里打开这个项目的会话，并把提示词填好。

DSH 0.2.1 的客户端已经具备这件事的完整通路：`uiWorkspace.startSession(workspaceId, { prompt, whenDraftExists })` 会在指定 workspace 打开（或复用空白）会话，并通过 `conversation.input.requestDraftInitialization` 把提示词写进输入框——**只填不发**。所以这次不新增宿主路由，只加一层客户端接线。

接口出处（`app.asar` 内的实际代码，和 `docs/dsh-plugin-api.md` §6.6 一致）：`dsh-client-ui-workspace/lib/client.js:1500-1542`（`startSession`，`:1418-1431` 复用空白会话，`:1529-1536` 初始化草稿）、`dsh-client-ui-conversation/lib/client.js:15110-15131`（`replace` / `keep` / `append` 语义）、`dsh-api-workspace-controller/lib/client.js:389`（`workspaces` 服务与 `list` 快照）。

## 决定

- **头部主按钮改为 `✦ 交给 AI 助手`**：点击 → 匹配仓库所属 workspace → `startSession` 打开该 workspace 的会话 → 输入框里是提示词，光标就位，未发送。面板随之让位给会话（`main` 槽位切换），这就是结果反馈。
- **匹配用客户端自己的 `workspaces` 服务**：`items[]` 里的 `workspaceId/path` 与 `startSession` 用的是同一份数据，避免宿主 id 与客户端 id 对不上的问题。取「路径等于仓库根，或仓库根位于其下」的最长匹配，所以嵌套 workspace 也能选对。
- **提示词跟随面板语言**，包含仓库绝对路径、文件相对路径、分支、冲突块数，以及边界：只改这个文件、改完用一两句话说明、不要 `git add`/`commit`/`checkout`，由人在面板里标记为已解决。不写「正在合并某分支」——面板没有可靠的合并来源，冲突标记本身会告诉 Agent 两边是谁。
- **失败有明确出口**：仓库不在已注册 workspace（或旧版 DSH 没有开放会话）时，**自动**把提示词复制到剪贴板并弹框说明原因——正常情况框里只有原因和「关闭」，因为文本已经在剪贴板上了；只有自动复制失败时，框里才显示完整提示词和「复制提示词」按钮。打开失败超过 4 秒同样走这条路径。面板永远不因为交不出去而卡住。
- **`whenDraftExists: 'replace'`**：点击是「把这个文件交出去」的显式动作，空白会话里上一次同样的交接应当被替换，而不是叠在一起。
- **旧的模型合并降级、不删除**：移到冲突文件行的右键菜单「用模型合并（预览）」，宿主那四条 `conflict/*` 路由与预览对话框保持原样。头部只留一个 AI 入口，但能力没有丢；是否删除留作后续单独决定。
- **不做**：自动发送、往已有会话里追加、批量把整个冲突交给 AI、交出去后在会话里插入提示、面板侧记住哪些文件已交出去。

## 结果

- 新增 `src/client/handoff.ts`（workspace 匹配、`startSession` 调用、提示词组装）与 `HandoffDialog`；`Workspace` 增加交接状态与失败回退，`DiffView` 头部按钮换成主操作，冲突行右键菜单增加两个 AI 入口。
- 测试新增 5 条（匹配优先级、只填不发、降级、提示词组装、UI 契约），总计 135 条全绿。
- 沙盒实测（隔离的 `DSH_HOME` + 真实冲突）：点击后面板让位，会话在该仓库 workspace 打开，输入框里是完整提示词、未发送；把 workspace 从注册表移除后，弹框说明原因且提示词已自动进剪贴板。
- 已知边界：面板在 1024 以下宽度本来就挤（三栏固定 rail 的历史问题），这次没有扩大范围去重做窄屏布局。
