# 本地 Git 工作台：历史视图 / 搜索视图 / 分支检出与分支操作

> 目标版本：0.3.0（本地优先，不做远端）。
> 2026-10-21 注：本 spec 里“不做远端 / 不为 push 预留按钮”的条款已被 [`docs/adr/0001-push-and-merge-semantics.md`](../adr/0001-push-and-merge-semantics.md) 取代；其余（历史 / 搜索 / 分支）仍然有效。
> 承接 0.2.0 的「可写工作区」；本 spec 补齐 Sourcetree 的三个工作区视图与分支交互。
> 已发布：GitHub issue [#13](https://github.com/chzisnull/dsh-git-tree/issues/13)，标签 `ready-for-agent`。本文件是可编辑副本，改动后请同步到 issue。

## Problem Statement

0.2.0 的面板能看改动、能暂存、能提交，但左栏的「历史 / 搜索 / 分支」只是摆设：行在那儿，点了没有任何反应；分支不能切换，也不能新建、删除、重命名。用户想要看某个文件的历史、找回一次提交、切到另一条分支继续工作，仍然必须离开 DSH 去开终端或 Sourcetree。

把入口做成看起来能点的样子却不响应，比根本没有入口更糟：用户会反复点击，然后怀疑插件坏了。

## Solution

把面板补成一颗**本地 Git 工作台**，三个工作区视图共用同一套引用树：

1. **文件状态视图**（已有）：改动、暂存、提交。
2. **历史视图**（新）：提交泳道图 + 描述 / 短 SHA / 作者 / 日期五列；选中提交后，下半区显示提交详情与"该提交改了哪些文件 + 单文件 diff"；支持「所有分支 / 仅当前分支」过滤、分页加载（每页 200 条）。
3. **搜索视图**（新）：同一个提交列表，加搜索框，支持按提交信息、作者、文件路径过滤（「这个文件被哪些提交改过」）。
4. **引用树可交互**：单击分支行打开该分支的历史；双击或行菜单「检出」切换分支；行菜单可新建、重命名、删除本地分支；标签单击跳到该标签的提交。
5. **本地安全动作**：工具栏加「在 Finder 中显示」「在终端打开」；分支切换前检查脏工作区，拒绝并说明原因，绝不自动 stash。
6. **不做远端**：远端分支、fetch / pull / push 全部不出现，也不做灰按钮。

## User Stories

1. 作为使用者，我想单击左栏的「历史」进入历史视图，这样我不用离开 DSH 就能回看提交。
2. 作为使用者，我想在历史视图看到每个提交的泳道、描述、短 SHA、作者和日期，这样我能快速定位一次提交。
3. 作为使用者，我想在历史列表里点一条提交就看到它的完整信息和变更文件，这样我不用再敲 `git show`。
4. 作为使用者，我想在提交详情里点某个文件看到它的 diff，这样我能确认这次提交到底改了什么。
5. 作为使用者，我想点提交详情里的父提交短 SHA 跳到父提交，这样我能顺着历史往回走。
6. 作为使用者，我想在历史视图切换「所有分支 / 仅当前分支」，这样我能区分本地全部历史与当前线的历史。
7. 作为使用者，我想让历史列表分页加载，这样即使有上千个提交面板也不会卡住。
8. 作为使用者，我想在历史里看到分支和标签 chip，这样我知道哪条提交是某个分支的尖端。
9. 作为使用者，我想单击搜索视图的输入框就能搜提交，这样找历史提交不用背命令。
10. 作为使用者，我想按提交信息或作者搜索，这样我能找回「上周谁改的那次」。
11. 作为使用者，我想按文件路径过滤提交，这样我能追一个文件的完整历史。
12. 作为使用者，我想搜索无结果时看到明确的空状态，这样我不会以为搜索卡住了。
13. 作为使用者，我想单击左栏的分支行进入该分支的历史，这样我在分支之间浏览不用切换工作区。
14. 作为使用者，我想双击分支行就检出该分支，这样切换分支只需要一个动作。
15. 作为使用者，我想在分支行菜单里检出分支，这样不用记双击这个隐藏操作。
16. 作为使用者，我想在脏工作区时切分支被明确拒绝并告诉我原因，这样我不会丢掉未提交的改动。
17. 作为使用者，我想看到当前分支在引用树里有明确标记，这样我随时知道自己在哪条分支上。
18. 作为使用者，我想新建本地分支并指定起点，这样我能从当前提交开一条新线。
19. 作为使用者，我想重命名本地分支，这样命名错了不用回终端。
20. 作为使用者，我想删除本地分支，这样清理临时分支不用回终端。
21. 作为使用者，我想删除未合并的分支时被拒绝并收到提示，这样我不会误删还没合并的工作。
22. 作为使用者，我想当前分支不能被删除，这样我不会把自己卡在 detached HEAD。
23. 作为使用者，我想单击标签跳到该标签对应的提交，这样我能快速回到一个发布点。
24. 作为使用者，我想在工具栏把仓库在 Finder 中显示，这样我能用系统文件管理器继续处理文件。
25. 作为使用者，我想在工具栏打开终端并落在仓库目录，这样需要原生命令时不用自己 cd。
26. 作为使用者，我想左栏的「远程」入口不再出现，因为这一版不支持远端，这样我不会误以为它坏了。
27. 作为使用者，我想历史 / 搜索里的写操作（新建、删除、重命名、检出）失败时有可读原因，这样我知道下一步做什么。
28. 作为使用者，我想切换仓库后历史、搜索、分支树都跟着切换，这样多仓库体验一致。
29. 作为使用者，我想浅色和深色模式下泳道图和提交详情都可读，这样不用为深色重做设计。
30. 作为使用者，我想界面文案跟随 DSH 的中英文，这样它和宿主一致。
31. 作为维护者，我想历史解析、泳道分配和分支操作都有路由级测试，这样后续加功能不用重建安全网。
32. 作为维护者，我想写操作（检出、分支增删改）的路径与分支名校验在进入 argv 前完成，这样面板不会成为命令注入的入口。

## Implementation Decisions

### 视图模型

- 工作区视图是枚举：`status`（默认）/ `history` / `search`。左栏 WORKSPACE 三项变成真正的按钮，当前视图有选中态；`history` 与 `search` 共用同一个提交列表组件，差别只在搜索框是否常驻与初始焦点。
- 视图状态在客户端内存中，不持久化；切换仓库时回到 `status`，并清空历史选中项。
- **不再有任何"看起来能点但不响应"的元素**：要么有行为，要么明确禁用并给出原因。

### 历史与提交

- 历史数据来自一次有界 `git log`：`--branches`（或 `HEAD`）→ `--date-order`/`--topo-order` → 自定义字段分隔符，输出 `sha`、`parents`、`author`、`authorEmail`、`date`（ISO 严格格式）、`subject`、`refs`。分页用 `limit` / `skip`，每页 200 条。
- **泳道分配在宿主完成**：纯函数按提交顺序维护活跃 lane 列表，合并提交分配现有 lane 或新 lane，输出每个提交的 `lane` 与 `parentLanes`；客户端只画点、竖线与合并斜线，不自己算布局。泳道数上限 8，超出复用颜色。
- 提交详情来自一次 `git show` 系调用（`--no-patch` 取元信息 + `--name-status` 取文件），同时给出指向该提交的本地分支与标签（refs），父提交列表按顺序给出。
- 提交内单文件 diff 复用现有 diff 路由，加 `commit=<sha>` 参数；渲染器不变。
- 历史列表行结构：`泳道图 | 描述（subject + refs chip）| 短 SHA | 作者 | 日期`；行高 22，选中行整行高亮；列表底部「加载更多」。
- 第一行可选的「未提交改动」入口本期不做（文件状态视图已经承担）。

### 搜索

- 搜索复用历史路由，参数为 `query`（匹配 subject/author）、`author`、`path`、`scope=all|current`；大小写不敏感，`--fixed-strings` 避免正则注入。
- 搜索视图：顶部固定搜索框 + 「全部 / 当前分支」切换 + 结果列表；结果行与历史行相同，点击进入同一个提交详情。
- 空查询时显示提示而不是空列表；无结果显示「没有匹配的提交」。

### 分支与标签

- 引用树只保留本地分支与标签；**远程分组整个移除**（不做远端）。
- 单击分支行 → 历史视图并过滤到该分支（`scope=branch:<name>`，实现上作为 `--branches=<name>`）；双击 / 行菜单「检出」→ 检出。当前分支行单击也进历史，图标保留当前标记。
- 分支行菜单项：检出、在新分支上查看？否——只保留：检出、重命名、删除、复制分支名。
- 新建分支入口：分支分组标题右侧「+」，弹出一个小输入框，填写分支名与起点（默认当前 HEAD），校验分支名。
- 删除分支：`git branch -d`（安全删除），未合并会失败并把 git 的原因翻译成可读提示；当前分支禁止删除；不做 `-D`。
- 重命名：`git branch -m`；目标已存在时拒绝。
- 检出安全：先读 porcelain 状态；存在暂存 / 未暂存 / 冲突 → 拒绝，返回 409 `dirty-worktree`，提示「有未提交改动，先提交或交给 Agent」。未跟踪文件不阻止检出（与 git 自身行为一致），但若 git 仍拒绝则原样翻译原因。**绝不自动 stash、绝不清工作区。**
- 标签只有单击导航（进入该标签的历史），不做标签的增删。

### 本地安全动作

- 工具栏新增两个图标按钮：在 Finder 中显示、在终端打开。宿主用 `open`（Finder）与 `open -a Terminal`（终端）执行，`cwd` 仍是当前选中仓库；命令参数固定，不拼接用户输入。
- 这两个动作在非 macOS 上不出现（按平台能力裁剪），不做假按钮。

### 宿主契约（新增/扩展）

- `GET /api/git-tree/history`：`cwd`、`limit`、`skip`、`scope`、`query`、`author`、`path`；返回 `{ commits: [{ sha, parents[], lane, parentLanes[], author, authorEmail, date, subject, refs[] }], laneCount, hasMore }`。
- `GET /api/git-tree/commit`：`cwd`、`sha`；返回 `{ sha, subject, body, author, authorEmail, date, parents[], refs[], files: [{ path, status, additions?, deletions? }] }`。
- `GET /api/git-tree/diff` 增加可选 `commit` 参数；与 `path` 组合时显示该提交中该文件的 diff。
- `POST /api/git-tree/checkout`：`{ branch }`；脏工作区 → 409 `dirty-worktree`；分支不存在 → 404 `unknown-branch`。
- `POST /api/git-tree/branch/create`：`{ name, start? }`；名非法 → 400 `invalid-branch-name`；已存在 → 409 `branch-exists`。
- `POST /api/git-tree/branch/delete`：`{ name }`；当前分支 → 409 `current-branch`；未合并 → 409 `branch-not-merged`（携带 git 的原因）。
- `POST /api/git-tree/branch/rename`：`{ from, to }`。
- `POST /api/git-tree/open`：`{ target: 'finder' | 'terminal' }`。
- 所有写路由沿用既有守卫：JSON body 校验、`--` 前置、cwd 限定在已注册 workspace、无 shell、有输出与时间上限。

### 客户端

- 左栏：WORKSPACE 三项（文件状态 / 历史 / 搜索）作为视图切换；分支行可点击、可双击、有行菜单；标签行可点击；远程分组移除。
- 历史视图：工具条（所有分支 / 仅当前分支）、表头、提交行、加载更多、提交详情区（详情字段 + 文件列表 + diff）。
- 搜索视图：搜索框、范围切换、结果列表、空态。
- 泳道图用主题 token 派生颜色（`color-mix`），不引入第二套色板；深浅色都要可读。
- 所有新文案进 en / zh 字典。
- 切换仓库、切换视图、检出成功后都重新拉取引用树与当前视图数据。

### 版本

- 0.3.0。远端相关能力整体不做，README 状态表如实标注。

## Testing Decisions

- **好测试的定义不变**：只断言外部可观察行为——HTTP 状态码、JSON 契约、传给 git 的 argv、以及写操作前后的状态迁移；不断言内部函数名或 CSS 类名。
- **仍然只有一个测试缝隙：宿主 HTTP 路由边界。** 沿用 `apply()` + 假 context + 按 argv 路由的假 subprocess；新功能全部从这个缝隙测试，不新增第二个缝隙。
- **宿主纯函数模块**（历史解析、泳道分配、分支名校验）放在已有的 `host-modules` 测试里直接导入测试，它们仍属于同一缝隙的补充，不新建测试基建。
- **需要覆盖的宿主行为**：
  - 历史：分页参数、字段解析、refs 归属、merge 提交的 parentLanes、lane 上限与复用、空仓库；
  - 搜索：query/author/path 三种过滤的 argv（`--fixed-strings`、`--grep`、`--author`、`--` 路径分隔）、无结果；
  - 提交详情：元信息 + name-status 文件列表、父提交顺序、refs 列表；
  - 提交内 diff：`commit` 参数的 argv 组合；
  - 分支：检出的脏工作区拒绝（不执行 git）、未知分支、新建/删除/重命名成功与三类拒绝（当前分支、未合并、已存在）、非法分支名在进入 argv 前被拒；
  - open：Finder / 终端两套固定 argv，平台不支持时降级；
  - 跨仓库：所有新路由都走已注册 workspace 的 cwd 校验。
- **先例**：`test/routes.test.mjs` 的假 context + argv 路由写法；`test/host-modules.test.mjs` 的解析器测试；`test/client-boot.test.mjs` 的客户端启动契约；`test/ui-contract.test.mjs` 的 bundle 契约（新增路由名、slot 数量不变、只用主题 token）。
- **手工验收清单**（写回 issue）：
  - 单击历史 / 搜索 / 分支行都有响应，且没有假可点元素；
  - 1000 提交仓库：首屏 200 条、加载更多可用、滚动不掉帧到不可用；
  - 双击分支检出成功、脏工作区检出被拒且提示可读；
  - 新建 / 重命名 / 删除分支各成功一次，未合并删除被拒；
  - 提交详情与 `git show --stat` 对得上；
  - Finder / 终端打开落在当前仓库目录；
  - 深色模式下泳道与 diff 可读。

## Out of Scope

- 远端相关的全部能力：远程分支、fetch、pull、push、远端管理。
- 合并、变基、cherry-pick、冲突解决 UI。
- stash / submodule / subtree。
- 在 diff 内容里全文搜索（只按提交信息 / 作者 / 文件路径搜）。
- 提交图的完整 Sourcetree 品质（斜线、八向颜色、标签布局），本期是简化泳道。
- 大仓库虚拟滚动（按此前决定不做；用分页 + 加载更多控制 DOM）。
- 右侧栏窄面板、与 Agent 共用操作、多仓库工作区切换（仓库切换已在 0.2.0 完成）。

## Further Notes

- 本轮的设计依据仍是 `docs/sourcetree-ui.md` §8（历史视图布局、泳道参数、五列宽度、行高 20.5）与 §10 的交互流；Sourcetree 里单击分支 = 看该分支历史、双击 = 检出，本 spec 采用同一语义。
- `GLOSSARY.md` 已补：History view、Search view、Lane、Checkout、Dirty working copy、Commit detail、File status view。
- 用户已明确「不考虑远端」，因此引用树的「远程」分组直接移除，不保留禁用态。
- 版本发布仍走既有链路：`npm test` → 构建 → 提交推送 → npm 发布；发布后需重启 DSH 才能加载新的宿主半。
- 若后续要做远端，`refs` 解析与 remote 分组可以直接恢复，但本 spec 不为它预留灰按钮。
